# 卒業ゲート チェックリスト（プロト → 昇格）

プロト tier から昇格 tier へ上げる前に **全項目を満たす**こと。
1 つでも欠けるならプロトのまま（= 運用ゼロ、未達なら sunset）。
未記入で昇格させると「検証用オモチャに本番運用コストを払う」死因に直結する。

## 1. 問題検証済みか（North Star）
- [ ] 検証すべき問題／North Star が明文化されている（`memory/decisions.md`）
- [ ] 実データ・実利用で当たったと言える根拠がある
- [ ] 「使い捨てにせず運用コストを払う」理由が説明できる

## 2. オーナー確定か
- [ ] 説明責任オーナー（人間・1 人）が決まっている
- [ ] オーナーが役割（一次対応・意思決定・撤退判断）を了承している

## 3. 撤退条件定義済みか
- [ ] sunset 条件が数値／事象で定義されている
- [ ] 撤退手順が runbook に書かれている

## 4. セキュリティ & 秘匿情報点検
- [ ] 秘密情報の直書きなし（code-review の review-no-secrets 相当を通過）
- [ ] シークレット管理経路（env / シークレットマネージャ）が確立
- [ ] Git 運用ガバナンス（PR 必須・保護ブランチ / force 禁止フック）が有効

## 5. 最小監視
- [ ] 死活・エラー率の最小メトリクスとアラート先がある
- [ ] runbook の「障害一次対応手順」が埋まっている

## 6. 依存更新経路
- [ ] 依存・脆弱性の自動 PR（Dependabot / Renovate 等）が設定済み
- [ ] 更新 PR のレビュー・マージ責任が明確

---
全チェック → 昇格可。runbook（`maintenance-runbook.template.md` を複製）を
`memory/ops/` に作成し `tasks.md` から参照する。
