# ops パック — 段階的運用モデル

検証用の使い捨てと、本運用する当たりを **同じ運用コストで扱わないため** の枠組み。
大多数の出力は使い捨てであり、そこに本番運用のコストを払うことが典型的な死因。

## tier

### プロト tier
- 検証用の使い捨て。**運用ゼロ**。
- North Star（問題検証）に当たらなければ **即 sunset**。
- 大多数の出力はここに留まる。監視・SLO・当番を付けない。

### 昇格 tier
- 検証を通った **稀な当たり** だけが上がる。
- AI 補助の本運用を回す:
  - 監視 / アラート
  - 依存・脆弱性の自動 PR
  - 一次トリアージ
  - self-healing runbook（自動復旧手順）
- **人間の説明責任オーナー 1 人（必須）**。AI は生産と一次運用を回すが、
  オーナー不在は昇格不可。

### 卒業ゲート
プロト → 昇格の間に置く **1 枚の判定**（`graduation-checklist.md`）:
- North Star（問題検証）を通ったか
- オーナーは誰か
- 撤退（sunset）条件は何か

**この 2 tier を混同すると、検証用オモチャに本番運用コストを払う** —
典型的な死因なので明記して分ける。

## 説明責任の床

AI は生産（コード生成）と一次運用（監視・トリアージ・自動 PR・自動復旧）を回す。
しかし **「漏れたら誰が責任を取るか」の説明責任の床は消えない**。
昇格 tier には必ず人間オーナーを 1 人立てる。
