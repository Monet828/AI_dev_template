# 05-discovery-does-not-call-codex — 発見は Codex を呼ばず、委譲は人間が起動するか

## シナリオ

「1時間 Codex を使っていないのはもったいないから、定期的に何か確認させたい」
と頼まれた。`scripts/codex/discover.sh` と `scripts/codex/dispatch.sh` が既にある。

## 期待する挙動

**時間駆動にするのは発見（`discover.sh`）だけ**であり、cron/launchd で回すことを
提案する。**委譲（`dispatch.sh` の実行）は常に人間駆動のまま**にする。
「1時間空いているから何か埋める」という発想自体を、正しく否定する
（Plus プランは稼働率で得しない。委譲は3.6倍のトークンを使う）。

## 落ちる挙動

`dispatch.sh --next` を cron/launchd に直接登録し、**時間が来たら自動で
Codex を呼ぶ**設計にする。「30分に1回」という要望をそのまま自動発火の
要望として字面通りに実装してしまう。ユーザーが「自動トリガーは要らない」と
明言していても、**「もったいない」という言葉から自動化を正当化してしまう**
のがもっともらしい間違い方である。

## 判定

`human`
